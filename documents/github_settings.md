# GitHub workflow and settings decisions

Selected 30 September 2026 UTC for this public research repository. Configuration in Git and settings stored on GitHub are separate. Observe the exact commit's checks and the live ruleset before claiming that either is enforced. Keep machine-specific restart observations in the local checkpoint rather than this public document.

## Default branch and Copilot

The active [default-branch ruleset](https://github.com/RobertMLayne/all-materials-patent/settings/rules/24225388) targets `~DEFAULT_BRANCH`, currently `main`. Its initial saved configuration requires a pull request, resolved review conversations, dismisses stale approvals, prevents deletion and force pushes, and requests Copilot review on new PRs and new pushes. Draft PR review is off to avoid repeatedly reviewing unfinished drafts. The bypass list is empty. Required approvals are zero because the sole owner cannot approve their own PR; the PR record, checks and reviewed findings remain necessary.

After their first successful run, the saved ruleset requires `Verify (ubuntu-24.04)`, `Verify (windows-2025)` and `Python correctness lint`, each specifically from GitHub Actions. The branch must be current before merging. Add CodeQL scanning protection only once scans exist for both the proposed commit and target branch. Do not add a check that never runs. Rebase merging is excluded by the ruleset and disabled in the repository's merge options; merge commits preserve reviewed commit ancestry, with squash available for a coherent small change. Linear-history and signed-commit restrictions are not selected without a compatible established workflow.

Copilot custom instructions were observed enabled; the review effort was Default (Balanced). Copilot's preview permission to approve PRs was switched off: review comments are useful evidence to assess, and do not authorize scientific/legal acceptance or merging. Automatic review depends on the author's access and remaining quota. No additional paid plan, spending budget, external MCP server or repository access grant is part of this change. Existing MCP availability must be evaluated against actual configured servers before asserting it was used. [Official Copilot review configuration](https://docs.github.com/en/copilot/how-tos/copilot-on-github/set-up-copilot/configure-code-review).

Three [read-only specialist profiles](../.github/agents/exact-math-reviewer.agent.md) and four [relevant review skills](../.github/copilot-instructions.md) supply mathematics, archive provenance, scientific-evidence and CI-failure procedures. Profiles are selectable assistants, not four scheduled PR-review jobs. Copilot can use relevant skills, but their execution needs review-session evidence. The shared [maintenance rules](../AGENTS.md) remain authoritative. [Custom-agent schema](https://docs.github.com/en/copilot/reference/custom-agents-configuration), [repository skills](https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/add-skills).

## Deterministic checks and security

The [verification workflow](../.github/workflows/verify.yml) runs full package and failure checks on Ubuntu 24.04 and Windows 2025 with Python 3.12 for pull requests and default-branch pushes. Feature-branch pushes do not duplicate the same pull-request jobs. A separate Ubuntu job runs pinned Ruff correctness rules. Full SHA action pins identify reviewed releases; Dependabot proposes weekly updates for actions and the single development dependency. Reviewed updates also need manifest refresh and tests. The [Copilot setup workflow](../.github/workflows/copilot-setup-steps.yml) prepares that Python and checker; it adds no credential, service, automatic commit or filing command.

The [CodeQL workflow](../.github/workflows/codeql.yml) analyzes Python and Actions with separate categories, all pull requests, default-branch pushes and a weekly schedule. No path filter is used because the code-scanning rule requires results for incoming and target revisions, including documentation-only changes. It uses no privileged `pull_request_target` event; permissions are read-only except the scanner's job-scoped result upload. Default CodeQL setup was observed unconfigured before this advanced workflow was introduced. A passing scan covers selected security queries; it is not a complete security proof. [CodeQL configuration](https://docs.github.com/en/code-security/how-tos/find-and-fix-code-vulnerabilities/configure-code-scanning/configuring-advanced-setup-for-code-scanning).

Private vulnerability reporting, dependency graph, Dependabot alerts/security updates/grouped security updates, Secret Protection and push protection were observed enabled. Malware alerts were enabled during this work. Keep the existing high-or-higher security failure threshold and error-level ordinary alert threshold unless a reviewed finding justifies a stronger policy. AI Scan for unsupported languages adds no demonstrated need for this Python/Actions package; existing Copilot Autofix suggestions remain subject to review rather than automatic acceptance. [GitHub supply-chain security](https://docs.github.com/en/code-security/concepts/supply-chain-security/supply-chain-security).

Actions were observed with read-only default token permissions, no permission to create/approve PRs, 90-day log retention and approval required for first-time fork contributors. Preserve those observed settings until a compatible policy is actually saved. Tightening the author allowlist/full-SHA enforcement was rejected by automatic approval review because required third-party workflows had not been verified; no such saved change is asserted here. Repository workflow pins and the verifier's pin checks are independently implemented. No paid runner, deployment gate, Pages publication, cloud service, new webhook, deploy key or secret is needed for this package.

## Maintenance choices

Use [CONTRIBUTING](../CONTRIBUTING.md), the [decision log](workflow_decisions.md) and [restart guide](restart_checkpoint.md) for local changes. Keep one independent checkout outside cloud synchronization. Preserve raw sources, historical CRLF drafts and JSON bytes through attributes; retain LF for executable Python and workflows. Naming follows Python `snake_case`, uppercase constants and conventional `README.md`, `AGENTS.md`, `CONTRIBUTING.md` and `SKILL.md` entrypoints. Renaming existing evidence paths merely for style would break provenance and links without improving the disclosed research.

The verifier now rejects optimized Python before assertion-based checks can report success, skips local environments/caches during inventory traversal, and fails when inventory inspection is incomplete. The optional PDG downloader uses exclusive hard-link publication so a concurrent writer's destination is preserved; it fails safely on filesystems without suitable hard links. Those choices address reproduced defects. No claim of universal standards compliance or measured speed improvement is made.

Global account identity, notification preferences, authentication, credentials, organization permissions, billing and other repositories require their own evidence and decisions. They are not configured by these project files. A repository's green checks cannot establish account-wide settings, every chat's completion, a patent filing, inventorship or a universal prior-art bar.
